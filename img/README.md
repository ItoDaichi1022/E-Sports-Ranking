# 画像

サイトに埋め込む画像を置く場所。大会やお知らせの画像はSupabase Storageなので、
ここに入るのは「サイトそのものの見た目に使う、差し替え頻度の低い画像」だけ。

| ファイル | 使い道 | 形式 | 目安 |
|---|---|---|---|
| `icon.webp` | ブラウザのタブのアイコン | **正方形** WebP 256×256 | 30KB以下 |
| `icon.png` | iOSのホーム画面のアイコンだけ（下記参照） | 同じ絵の PNG 256×256 | 40KB以下 |
| `game-logo.webp` | ホームの上に出すサイトのロゴ | 幅700px WebP（透過） | 100KB以下 |
| `characters/` | キャラクターの切り抜き（**自動生成**。下記参照） | WebP（透過） | 1枚90KB以下 |
| `character/` | 上の元になる配布素材（**普段は置かない**。下記参照） | PNG | — |

**ここに置く画像はWebPにする。**唯一の例外が `icon.png` で、iOSのホーム画面に
追加したときのアイコン（`apple-touch-icon`）だけはWebPを読んでくれないため、
同じ絵をPNGでも置いている。読まれるのはiOSのホーム画面に追加した人だけで、
ふだんのタブは全ブラウザ `icon.webp` の方を使う。

※ `game-logo` という名前は、以前ここに扱うゲームのロゴを置いていた頃のもの。
中身はサイト自身のロゴに変わったが、参照している場所を増やさないため名前は据え置き。

## 差し替えるとき

1. 同じ名前で上書きする（参照している場所を変えなくて済む）
2. **`game-logo.webp` を差し替えたときは、`index.html` の `<img id="hero-game-logo">` の
   `width` / `height` を新しい画像の実寸に書き換える**（現在は 700×623）。
   ここが実寸と合っていないと、画像を読み終えるまでのあいだ確保される場所の
   高さがずれる。とくに書き忘れて高さが 0 になると、ホームのロゴが
   スクロール演出（clip-path）で開かないまま出てこない。
   実寸は次で確認できる:

   ```bash
   node -e "const b=require('fs').readFileSync('img/game-logo.webp');console.log((b[24]|b[25]<<8|b[26]<<16)+1,'x',(b[27]|b[28]<<8|b[29]<<16)+1)"
   ```

3. `index.html` の `?v=` の数字をまとめて1つ上げる
   （上げないと、見ている人のブラウザが古い画像を使い続ける）
4. `node scripts/check-cache-version.mjs` で数字が揃っているか確認する

## 用意するときの決まり

**軽くすること。** ホームは初めて来た人が最初に開く画面なので、ここが重いと
第一印象がそのまま遅さになる。スマホで撮った画像やゲーム公式の配布素材は
数MBあることが多いので、そのまま置かない。目安は **100KB以下**。

`game-logo.webp` の作り方:

- **透過の余白を切り落とす。** 配布素材は上下左右に大きな透明の余白が入っている
  ことが多い。余白ごと表示すると、ロゴが小さく見えるうえに、その上下に
  説明のつかない空きができる。
- **幅700px程度に縮小する。** 画面に出るのは最大230pxで、高精細画面（3倍）でも
  690pxあれば足りる。元の解像度のまま置いても、きれいには見えない。
- **WebPで書き出す。** グラデーションの多いロゴはPNGだとほとんど縮まない
  （実測: 700px幅で PNG 400KB に対し WebP 52KB）。

アイコンは**正方形**にすること。横長のまま入れるとタブの中で縮んで潰れる。
256×256 あれば、スマホのホーム画面（180〜192px）にもタブ（16〜32px）にも足りる。
こちらは透過させず、背景まで含めた1枚の絵にしておくと小さくしても形が保たれる
（透過が全面不透明なら、アルファ面はただの無駄なので落とす）。

差し替えるときは、元絵1枚から2つ書き出す:

```bash
npm install --no-save sharp
node -e "const s=require('sharp');s('元絵.png').resize(256,256).removeAlpha().webp({quality:90,effort:6}).toFile('img/icon.webp');s('元絵.png').resize(256,256).removeAlpha().png({palette:true,quality:100,effort:10}).toFile('img/icon.png')"
```

ドット絵なので可逆WebPも試したが82KBで、`quality:90` の25KBと256pxでは
見分けが付かなかった。タブは16〜32px、iOSのホーム画面でも180pxなのでこれで足りる。
PNGはパレット化しないと4倍近く膨らむ（139KB → 36KB）。

## キャラクターの画像（`character/` と `characters/`）

**名前が1文字違うだけの別物**なので、取り違えないこと。

| | 中身 | 大きさ | 配信 | Git | 手元 |
|---|---|---|---|---|---|
| `character/`（単数） | 公式の配布素材そのもの。26人ぶん226枚のPNG | **2.3GB**（1枚が最大145MB） | しない | しない | **普段は置かない** |
| `characters/`（複数） | サイトが実際に読む切り抜き | 10MB（452ファイルのWebP） | **する** | する | ある |

配布素材をそのまま置くことはできない。Cloudflare Pages は1ファイル25MiBまでで、
145MBのPNGを上げるとデプロイそのものが落ちる。落ちなかったとしても、
キャラクターを選ぶ画面に何百MBも流すわけにはいかない。
そこで元素材は `.gitignore` と `.assetsignore` の両方で外し、
そこから作った軽い複製だけを配る。

さらに `img/character/` は**作り直すときだけ置く**。Gitにも配信にも載らない以上、
2.3GBを作業機に常駐させても得るものが無いので、変換が済んだら消してよい。
出来上がりの `characters/` と `js/characterData.js` はGitに入っているので、
素材が無くてもサイトは動くし、他の人が clone しても足りないものは出ない。
`.gitignore` と `.assetsignore` の行は残してある ── また置いたときに、
うっかり2.3GBをコミットしたりデプロイしたりしないため。

### 作り直す

キャラクターを足す・スキンが増えた・切り抜き方を変えたいときだけ:

```bash
# 1. 配布元から img/character/<英語名 日本語名>/ の形で素材を取り直す
npm install --no-save sharp        # 変換に使う。配信物には含まれない
node scripts/build-characters.mjs  # 画像と js/characterData.js を作り直す
node scripts/check-cache-version.mjs
# 2. 済んだら img/character/ は消してよい
```

素材が無い状態で流すと、何をすればいいかを書いて止まる（黙ってENOENTにはならない）。

- 作られるのは 角240px（選ぶ画面の一覧用）と 長辺480px（大きく見せる用）の2枚ずつ
- `js/characterData.js` の `ASSET_VERSION` は自動で1つ上がる。
  `img/` は1年キャッシュされるので、これが上がらないと新しい絵が誰にも届かない
- **新しいキャラクターのフォルダを足したときは、`scripts/build-characters.mjs` の
  `ALIASES` にも足す**（足し忘れると例外で止まる）。
  ファイル名は開発中の内部名で付いていて公開名と一致しないため
  （ソフィア＝SnowWhite、S-17＝Athena）、この対応表が要る

素材のフォルダ名は `英語名 日本語名`（例: `Sivi シビ`）にすること。
ここからキャラクターIDと画面に出す名前を読み取っている。

## 背景の透過について

`game-logo.webp` は**背景が透過**のものが一番きれいに出る（黒い画面にロゴの色が
そのまま乗る）。白背景の画像でも構わない ── その場合は `js/app.js` が画像の四隅を
見て自動で判定し、白い台紙に載った印の形で表示する（黒い面に白い四角が
そのまま出てしまうのを避けるため）。画像そのものが無いときは、
ホームのそのブロックごと出さない（割れた画像を見せない）。
